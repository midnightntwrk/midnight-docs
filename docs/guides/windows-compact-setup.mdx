This guide walks you through setting up the Midnight development environment on Windows using Windows Subsystem for Linux (WSL). It covers installing and configuring WSL, Docker Desktop, the Midnight proof server, the Compact compiler, and the Compact VS Code extension.

By the end of this guide, you have a development-ready environment for building DApps on the Midnight Network, running the proof server, and interacting with the network.

## Prerequisites

Before starting, verify your system meets the following requirements:

| Requirement | Details |
|-------------|---------|
| **Windows version** | Windows 10 version 2004+ (build 19041) or Windows 11, required by the WSL installation command used in this guide. WSL 2 requires Hyper-V support. |
| **Virtualization** | Enable hardware virtualization (Intel VT-x or AMD-V) in your BIOS/UEFI. |
| **Admin rights** | You need administrator privileges to install WSL and Docker Desktop. |
| **Disk space** | At least 10 GB of free space for Ubuntu, Docker images, and the Compact toolchain. |
| **Internet** | Stable connection for downloading distributions, Docker images, and GitHub release artifacts. |

### Verify virtualization

Open PowerShell as Administrator and run:

```powershell
systeminfo | findstr /B /C:"Hyper-V Requirements"
```

**Expected output:**

```text
Hyper-V Requirements:      VM Monitor Mode Extensions: Yes
                             Virtualization Enabled In Firmware: Yes
```

If the output shows virtualization as off, reboot into your BIOS/UEFI settings (usually by pressing `F2`, `Del`, or `F10` during startup). Then enable **Intel VT-x** or **AMD-V** in the CPU/Security settings.

If the command instead prints `A hypervisor has been detected`, virtualization is already active and no BIOS change is needed.

## Install Ubuntu

Developing DApps for the Midnight Network often requires Linux-based tools, such as the proof server. The Windows Subsystem for Linux (WSL) lets you run a native Linux environment inside Windows without the overhead of a traditional virtual machine.

1. Open the Start menu, search for **Windows PowerShell**, right-click the result, and select **Run as administrator**. You need administrator privileges to install system-level features like WSL.

2. In the PowerShell window, run:

   ```powershell
   wsl --install -d Ubuntu
   ```

   This single command enables the required Windows features: Virtual Machine Platform and Windows Subsystem for Linux. It also downloads and installs the Ubuntu distribution and restarts the necessary services.

   :::info[Installation time]
   The initial download and installation can take 5 to 15 minutes, depending on your internet connection and system speed. Do not close the window until the process is complete.
   :::

3. When the installation completes, a new Ubuntu terminal window opens automatically and prompts you to create a UNIX username and password. Enter both. If no window opens, restart your computer, then launch **Ubuntu** from the Start menu to finish setup.

   :::info[Password entry]
   When entering your password, the terminal does not display characters on the screen for security reasons (this is standard Linux terminal behavior). Type your desired password carefully and press Enter.
   :::

4. Confirm the setup succeeded: your terminal prompt shows your new username (for example, `yourusername@DESKTOP-XXXXXX:~$`). Ubuntu is now ready to use.

### Verify the WSL version

To ensure WSL is running the correct version, execute this command in Windows PowerShell:

```powershell
wsl -l -v
```

**Expected output:**

```text
  NAME      STATE           VERSION
* Ubuntu    Running         2
```

You should see Ubuntu listed with STATE `Running` and VERSION `2`. WSL 2 provides optimal performance and Docker integration.

If Ubuntu is on VERSION 1, convert it with:

```powershell
wsl --set-version Ubuntu 2
```

## Install and configure Docker Desktop

1. In your web browser, go to the official Docker website at [docker.com/products/docker-desktop](https://www.docker.com/products/docker-desktop) and download **Docker Desktop for Windows**. Ensure the installer matches your CPU architecture (for example, **Windows - AMD64** for most modern systems).

2. Run the downloaded installer (for example, `Docker Desktop Installer.exe`). During the installation, check the box for **Use WSL 2 instead of Hyper-V**. Docker needs this option to integrate with the Linux environment you just set up.

3. Follow the prompts to complete the installation. Restart your system if the installer asks you to.

4. Launch **Docker Desktop** from the Start menu. It takes a few moments to start up, showing the whale icon in your system tray.

### Verify Docker and enable WSL integration

1. With Docker Desktop running, open **Settings** (the gear icon).

2. Select **Resources**, then open the **WSL integration** tab.

3. Toggle on **Enable integration with my default WSL distro**, and specifically toggle on your **Ubuntu** distribution. This connection allows Docker to manage containers directly from your Linux terminal.

4. Verify Docker works inside WSL. Open your Ubuntu terminal and run:

   ```bash
   docker --version
   docker run hello-world
   ```

   **Expected output:**

   ```text
   Docker version 27.x.x, build xxxxxxx
   Hello from Docker!
   This message shows that your installation appears to be working correctly.
   ```

If you get `docker: command not found` inside WSL, confirm Docker Desktop is running and you have toggled WSL integration on. Then restart Docker Desktop.

## Set up and run the Midnight proof server

The Midnight proof server generates the zero-knowledge proofs your DApp needs to submit transactions. You run it via Docker for consistency.

### Download the Docker image

Pull the image from your Ubuntu terminal:

```bash
docker pull midnightntwrk/proof-server:8.0.3
```

Alternatively, search for `midnightntwrk/proof-server` in the Docker Desktop search field and download the image from there.

### Run the proof server

To start the proof server, open your **Ubuntu** terminal and run:

```bash
docker run -p 6300:6300 midnightntwrk/proof-server:8.0.3 -- midnight-proof-server -v
```

You should see output similar to:

```text
actix_server::server: starting service: "actix-web-service-0.0.0.0:6300", workers: 14, listening on: 0.0.0.0:6300
```

:::tip[Keep the terminal open]
The proof server **must** stay active to generate proofs when you deploy contracts and submit transactions.
:::

### Run the proof server in the background

If you prefer not to keep a terminal window open, run the proof server in detached mode:

```bash
docker run -d --name midnight-proof-server --restart unless-stopped -p 6300:6300 midnightntwrk/proof-server:8.0.3 -- midnight-proof-server -v
```

This command:
- `-d`: Runs the container in the background (detached)
- `--name midnight-proof-server`: Assigns a friendly name for easier management
- `--restart unless-stopped`: Automatically restarts the container if it crashes or if Docker restarts

**Verify the container is running:**

```bash
docker ps
```

**Expected output:**

```text
CONTAINER ID   IMAGE                                COMMAND                  CREATED         STATUS         PORTS                    NAMES
xxxxxxxxxxxx   midnightntwrk/proof-server:8.0.3   "/bin/sh -c 'midnigh..."   2 minutes ago   Up 2 minutes   0.0.0.0:6300->6300/tcp   midnight-proof-server
```

**Stop the background server:**

```bash
docker stop midnight-proof-server
```

**Restart it later:**

```bash
docker start midnight-proof-server
```

### Verify the proof server is accessible

From your Ubuntu terminal (or from your DApp project), test connectivity:

```bash
curl http://localhost:6300/health
```

**Expected output:** a JSON response containing `"status":"ok"` and a server timestamp:

```json
{"status":"ok","timestamp":"2026-07-16 11:00:29.736272088 +00:00:00"}
```

If the `curl` command hangs or returns `Connection refused`, verify the container is running with `docker ps`. Then check that another process is not already using port 6300.

## Install the Compact compiler

Compact is Midnight's smart contract language. Since you are using a Windows machine, install the compiler inside your WSL Ubuntu terminal so it works with the rest of the Midnight toolchain.

1. Open your Ubuntu terminal (WSL).

2. Run the following command to install the Compact binaries:

   ```bash
   curl --proto '=https' --tlsv1.2 -LsSf https://github.com/midnightntwrk/compact/releases/latest/download/compact-installer.sh | sh
   ```

   To inspect the script before running it, download it first with `curl -O`, review it, and then run `sh compact-installer.sh`.

3. The installer script automatically updates your `PATH`. To apply the change to your current session, reload your shell configuration:

   ```bash
   source ~/.bashrc
   ```

4. Verify the installation by checking the version:

   ```bash
   compact --version
   ```

   **Expected output:**

   ```text
   compact x.x.x
   ```

5. Run `compact update` to install the latest compiler toolchain:

   ```bash
   compact update
   ```

:::caution[Command not found]
If `compact --version` returns `command not found`, the installer did not update your `PATH` correctly. The installer places the `compact` binary in `$HOME/.local/bin`. Add it manually:

```bash
export PATH="$HOME/.local/bin:$PATH"
echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.bashrc
```

Then reload your shell with `source ~/.bashrc` and retry.
:::

## Install the Compact VS Code extension

The Compact VS Code extension provides syntax highlighting and real-time error checking, which is essential for writing smart contracts.

### Download the latest VSIX

The VSIX download link changes with each release. To always get the latest version:

1. Visit the Compact VS Code extension releases page: [midnightntwrk/releases/artifacts/vscode-extension](https://github.com/midnightntwrk/releases/tree/gh-pages/artifacts/vscode-extension)
2. Navigate to the **latest version folder** (for example, `compact-0.2.XX`)
3. Download the `.vsix` file listed there

Alternatively, download the latest VSIX from your Ubuntu terminal:

```bash
# Download the latest VSIX
latest_version=$(curl -sL https://api.github.com/repos/midnightntwrk/releases/contents/artifacts/vscode-extension | grep -o '"name": "compact-[^"]*"' | sed -E 's/.*"compact-(.*)".*/\1/' | sort -V | tail -1)
curl -L -o compact-vscode-extension.vsix "https://github.com/midnightntwrk/releases/raw/gh-pages/artifacts/vscode-extension/compact-${latest_version}/compact-${latest_version}.vsix"
```

### Install in VS Code

1. Open **VS Code**.
2. Go to the **Extensions** view (press `Ctrl+Shift+X`), click the **...** (More Actions) menu at the top-right of the extensions pane, and select **Install from VSIX...**.
3. Select the `.vsix` file you downloaded to complete the installation.

### Verify the extension is active

Open any file with a `.compact` extension (or create a test file like `hello.compact`). You should see syntax highlighting. If the file icon changes and keywords show color, the extension works correctly.

## Troubleshooting

### WSL

| Problem | Cause | Solution |
|---------|-------|----------|
| `The requested operation requires elevation` | PowerShell not run as Administrator | Right-click PowerShell and select **Run as administrator** |
| `WSL2 requires an update to its kernel component` | WSL kernel needs an update | Run `wsl --update` in PowerShell, then restart your computer |
| `Virtualization is not enabled` | Intel VT-x / AMD-V disabled in BIOS | Reboot into BIOS/UEFI and enable virtualization in CPU settings |
| Ubuntu terminal won't open | WSL installation incomplete | Run `wsl --install -d Ubuntu` again in Admin PowerShell |

### Docker issues

| Problem | Cause | Solution |
|---------|-------|----------|
| `docker: command not found` inside WSL | WSL integration not enabled or Docker not running | Open Docker Desktop → Settings → Resources → WSL Integration → Enable Ubuntu. Restart Docker Desktop. |
| `Cannot connect to the Docker daemon` | Docker Desktop is not running | Launch Docker Desktop from the Start Menu and wait for the whale icon to stop animating. |
| `port is already allocated` | Port 6300 is in use by another process | Find the process inside WSL with `ss -tlnp \| grep 6300`, or on Windows with `netstat -ano \| findstr 6300`, then stop it, or use a different port with `-p 6301:6300`. |

### Proof server issues

| Problem | Cause | Solution |
|---------|-------|----------|
| Proof server starts but DApp can't connect | WSL localhost forwarding stalled, or firewall blocking port 6300 | Restart WSL with `wsl --shutdown` and relaunch Docker Desktop, or add an inbound rule for port 6300 in Windows Defender Firewall. |
| Container exits immediately | Wrong command or missing flags | Verify you're using the exact command shown in the [Run the proof server](#run-the-proof-server) section. Check logs with `docker logs midnight-proof-server`. |

### Compact compiler issues

| Problem | Cause | Solution |
|---------|-------|----------|
| `compact: command not found` | `PATH` not updated after install | Manually add `~/.local/bin` to your `PATH` and reload `.bashrc` |
| `curl: (6) Could not resolve host` | DNS failure in WSL | Temporarily fix with `echo "nameserver 8.8.8.8" \| sudo tee /etc/resolv.conf`, or restart WSL with `wsl --shutdown` |
| VSIX won't install | Wrong VS Code architecture | Ensure you downloaded the standard VSIX, not an ARM64 version, unless you are on an ARM-based Windows device |

## Quick reference checklist

Use this checklist after completing each section to confirm your setup:

- [ ] Windows version 2004+ (build 19041) with virtualization turned on in BIOS
- [ ] WSL 2 running Ubuntu (`wsl -l -v` shows VERSION 2)
- [ ] Docker Desktop running with WSL integration toggled on
- [ ] `docker --version` and `docker run hello-world` succeed inside Ubuntu
- [ ] Proof server Docker image pulled and container running (`docker ps` shows it)
- [ ] `curl http://localhost:6300/health` returns the proof server JSON response
- [ ] Compact compiler working (`compact --version` prints a version)
- [ ] Compact VS Code extension active and syntax highlighting works on `.compact` files

Once you confirm every item, your environment is ready for Midnight development.
