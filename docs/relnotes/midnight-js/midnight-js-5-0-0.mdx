## High-level summary

Midnight.js 5.0.0 is the major release for the [ledger 9 network upgrade](/relnotes/ledger-9). After the upgrade, Mainnet accepts only ledger 9 transactions, so a DApp on Mainnet needs Midnight.js 5, wallet SDK 2.0.0, and indexer 4.4.100.

Midnight.js 5 works across both ledger eras. It can still call contracts deployed before the upgrade. Preview and Preprod stay on ledger 8 until a later upgrade. For those networks, keep using Midnight.js 4.1.1.

## Audience

This release note is relevant for developers who:

- Run a DApp on Mainnet
- Call contracts deployed on Mainnet before the ledger 9 network upgrade
- Use contract-to-contract calls
- Subscribe to contract actions through the indexer

## Summary of updates

- Builds and submits ledger 9 transactions for Mainnet after the upgrade.
- Refuses a ledger 8 transaction on a ledger 9 network before it submits. It throws `EraMismatchError` with the reason `ledger8-transaction-on-ledger9-network`.
- Calls contracts deployed before the upgrade through a retained ledger 8 path. After the upgrade, it refuses to deploy a new contract on that path.
- Adds a `ContractModuleProvider` for contract-to-contract calls. In this first phase, calls between contracts are bounded to unshielded data.
- Replays contract history by passing an explicit offset to contract action subscriptions on indexer 4.4.100.
- Tested together with Compact.js 3.0.0, Compact runtime 0.21.0, on-chain runtime 4.0.0, and wallet SDK 2.0.0.

## Breaking changes

TBD-L9[verify against final release notes]. The API was still changing in the release candidates, so check each item below against the final release.

### Required `providers.config`

Pass `providers.config` with `networkId` and `ttlSeconds` when you build your providers.

### Tagged result from `queryContractState`

`queryContractState` returns an object tagged with the ledger version, in the shape `{ version, ... }`. Read `version` before you decode the state.

### Ledger 9 transaction format

Transactions built in the ledger 8 format don't decode on ledger 9. Rebuild your DApp against Midnight.js 5 before Mainnet upgrades.

### Type surfaces are aware of the ledger era

Type surfaces that depend on the ledger now carry the ledger era. Code that assumed a single ledger era must select the era explicitly. Rebuild against the new API surface.

### Contract action subscriptions start at their offset

On indexer 4.4.100, a contract action subscription opened without an offset delivers only new actions. Midnight.js 5.0.0 passes an explicit offset, so it still replays a contract's history. Midnight.js 4.x does not pass an offset and receives no history.

### On-chain runtime package name

The on-chain runtime moves from the v3 line to the v4 line. The major version is carried in the package name rather than in a version range. If you depend on the on-chain runtime directly, change the dependency to `@midnight-ntwrk/onchain-runtime-v4`.

### Contract-to-contract calls use `ContractModuleProvider`

A DApp that makes contract-to-contract calls supplies a `ContractModuleProvider`. The `@midnight-ntwrk/midnight-js-bundled-contract-module-provider` package builds one from the compiled contract modules that your DApp ships, keyed by contract address. Pass it as `contractModuleProvider` in your providers. TBD-L9[confirm the package name against the final release]

### Exports named after their ledger

Public exports bound to a ledger version carry that ledger in their name. TBD-L9[renamed exports list]

## Contracts deployed before the upgrade

Contracts built with Compact toolchain 0.31.1 keep working after the upgrade without a recompile. Configure your ZK config provider with `verify: 'warn'`, because 0.31.1 output has no contract manifest. The upgrade rehearsal includes calling a contract deployed before the fork and deploying a contract compiled with Compact toolchain 0.36.0. TBD-L9[confirm after fork-survival test]

Midnight.js refuses contracts built with Compact toolchain 0.30.0 and throws `EraArtifactMismatchError`. Recompile these contracts before you call them on Mainnet.

If you recompile a contract that an earlier toolchain built, its verifier keys change even when the source hasn't. The new artifacts don't match the deployed contract, so Midnight.js refuses to attach to it with a verifier key mismatch. To keep calling the contract, keep its deployed artifacts. To move it to Compact toolchain 0.36.0, its maintenance authority inserts the new verifier keys with a maintenance update first. For how recompiling changes verifier keys, see the [ledger 9 upgrade page](/relnotes/ledger-9#recompiling-a-contract-changes-its-verifier-keys).
