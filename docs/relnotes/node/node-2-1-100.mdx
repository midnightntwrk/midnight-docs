## High-level summary

Node v2.1.100 is the node release for the [ledger 9 network upgrade](/relnotes/ledger-9) on Mainnet. The binary runs ledger 8 for blocks before the upgrade and ledger 9 for blocks after it.

Every Mainnet validator and RPC node must run v2.1.100 before the governance upgrade. A node that still runs [v1.0.400](/relnotes/node/node-1-0-400) cannot run the new runtime and stops importing blocks at the upgrade block.

The upgrade has two steps. First, node operators replace the binary. Then a governance action moves the on-chain runtime to ledger 9. The governance upgrade date is TBD-L9[fork date].

Preview and Preprod stay on node v1.0.400 and ledger 8.1.3 until a later upgrade. TBD-L9[Preview and Preprod upgrade date]

## Audience

This release note is relevant for users who:

- Run a Midnight node on Mainnet: validator, RPC, full, boot, or archive node.
- Run an indexer, a wallet backend, or other infrastructure that reads Mainnet blocks or runtime metadata.
- Build DApps or wallets that submit transactions to Mainnet.

If you run a node only on Preview or Preprod, keep running v1.0.400 for now.

## What changed (Summary of updates)

The updates below describe the key changes introduced in this release. They come from the release candidates and need checking against the final release. TBD-L9[confirm every item against the 2.1.100 release body]

- Added ledger 9 support. The node keeps ledger 8 for blocks before the upgrade and switches to ledger 9 at the governance upgrade.
- Removed ledger 7 support from the binary.
- Added a new runtime for the ledger 9 network upgrade. TBD-L9[runtime spec_version and transaction_version]
- Added two pallets: `SafeMode` and `C2MBridge`. The bridge pallet ships turned off until a governance action enables it. TBD-L9[bridge enabled at fork?]
- Removed three subcommands: `smart-contracts`, `sign-address-association`, and `sign-block-producer-metadata`.
- Changed the connection to Cardano db-sync to TLS only.

## Breaking changes

### Upgrade before the governance upgrade

The node binary and the on-chain runtime upgrade separately:

- **Binary upgrade:** you replace v1.0.400 with v2.1.100. This is a restart with no reset or resync. Until the governance upgrade, the node keeps running the current runtime and ledger 8.
- **Runtime upgrade:** a governance action moves Mainnet to the new runtime and ledger 9. The governance upgrade runs only after every validator runs v2.1.100. TBD-L9[confirm public wording of the validator gate]

A node that has not moved to v2.1.100 when the governance upgrade runs stops importing blocks at the upgrade block.

To upgrade your node:

1. Pull `midnightntwrk/midnight-node:2.1.100`, or download the node tarball for your architecture from the [node-2.1.100 release](https://github.com/midnightntwrk/midnight-node/releases/tag/node-2.1.100) and check it against the `SHA256SUMS` file. TBD-L9[confirm release tag and tarball names]
2. Check your configuration against the operator changes in the next section.
3. Restart the node with the new image or binary.
4. If you use the toolkit, switch to the toolkit version from the same release. TBD-L9[toolkit version]

Do this before TBD-L9[operator deadline before the fork].

To confirm the binary upgrade, call these RPC methods on your node:

- `system_version` returns a value that starts with `2.1.100`.
- Before the governance upgrade, `state_getRuntimeVersion` still returns `specVersion` `1000300`.

To confirm the runtime upgrade after the governance action:

- `state_getRuntimeVersion` returns the new `specVersion`. TBD-L9[runtime spec_version]
- `midnight_ledgerVersion` reports a ledger 9 version. TBD-L9[exact midnight_ledgerVersion output after the upgrade]

### Operator changes

These changes affect how you run the node. They come from the release candidates. TBD-L9[confirm operator changes against the 2.1.100 release]

- **Removed subcommands:** the `smart-contracts`, `sign-address-association`, and `sign-block-producer-metadata` subcommands no longer exist. Remove them from your scripts. The `wizards` subcommand stays.
- **db-sync connection:** the node connects to the Cardano db-sync PostgreSQL database over TLS only. The node ignores the `ALLOW_NON_SSL` setting. Set `ssl_root_cert` to turn on certificate checks. A node pointed at a PostgreSQL server without TLS exits at startup.
- **New flags:** `--no-hardware-benchmarks`, `--rpc-max-finality-subscriptions` (default 512), and `--ipfs-bootnodes`.
- **New configuration settings:** `storage_separation` (`separate` or `unified`, fixed at first start, environment variable `STORAGE_SEPARATION`) and `chainspec_c2m_bridge_config`.
- **Changed defaults:** `block_stability_margin` moves from 10 to 30, and `storage_cache_size` moves from 10000 to 100000.
- **Startup hardware benchmark:** the node runs a hardware benchmark at startup. Validators below the reference hardware profile get a warning. Use `--no-hardware-benchmarks` to skip it.

### Ledger 8 transactions stop working on Mainnet

After the governance upgrade, Mainnet rejects transactions built for ledger 8. Wallet SDK 1.x cannot sync or submit transactions on Mainnet. DApps and wallets need wallet SDK 2, Midnight.js 5, and the ledger 9 indexer (4.4.x). For the full version set, see the [support matrix](/relnotes/support-matrix). TBD-L9[final Mainnet versions in the support matrix]

Clients that read runtime metadata must fetch it again after the upgrade, because the runtime adds pallets and changes pallet error enums.

## What DApp developers do

You do not run a node, but your DApp talks to Mainnet through one. Before the governance upgrade:

- Move your DApp to wallet SDK 2 and Midnight.js 5, and point it at an indexer on the 4.4.x line.
- Contracts that you deployed before the upgrade with Compact toolchain 0.31.1 keep working without a recompile. Use a ZK config provider with `verify: 'warn'`. TBD-L9[confirm after fork-survival test]
- The network refuses artifacts built with Compact toolchain 0.30.0 with `EraArtifactMismatchError`. Recompile those contracts.
- Expect a short pause in user transactions right after the upgrade. Show your users a message that the network is upgrading and that they can retry.

For the full list of steps, see the [ledger 9 upgrade page](/relnotes/ledger-9).

TBD-L9[approved DUST wording: replace or confirm this paragraph]

At the upgrade, Mainnet resets its DUST state. The network replays DUST generation for cNIGHT automatically, at full cap, so Mainnet NIGHT holders do not need to register again. For about 3 minutes after the upgrade, the network rebuilds DUST and accepts no user transactions. NIGHT that you bridge to Midnight after the upgrade needs a first-time registration before it generates DUST.

## What indexer operators do

The ledger 9 indexer (4.4.x) needs a full re-index from genesis. Plan the re-index before the governance upgrade. A local archive node on v2.1.100 syncs the indexer faster than a public RPC endpoint. For details, see the [ledger 9 upgrade page](/relnotes/ledger-9).
