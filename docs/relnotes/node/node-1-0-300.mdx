## High-level summary

Node v1.0.300 is a security patch on the 1.0.x maintenance line. It includes a coordinated runtime upgrade for all networks. The new runtime imports Ledger8Bridge host functions that older node binaries cannot load, so every validator must run Node 1.0.300 before the runtime is enacted.

Devnet also uses a regenerated chain specification and genesis. Operators on devnet must reset their nodes to the new genesis. Preview, Preprod, and Mainnet keep their existing genesis and upgrade in place.

---

## Audience

This release note is for full node and stake pool operators, teams coordinating the runtime upgrade, and toolkit users who replay blocks from the 1.0.300 runtime.

---

## What changed

- The tblock correction is now gated by the on-chain runtime version instead of per-node configuration, so validators replay affected history consistently.
- The toolkit recognizes spec_version 1000300 and its metadata, allowing it to replay history produced by this runtime.
- The node, toolkit, and hardfork-test-upgrader images no longer include gdb.
- The bundled npm CLI was updated to clear the critical tar advisory GHSA-23hp-3jrh-7fpw.
- The devnet chain specification was rebuilt with the 1.0.300 runtime and populated reserve and ICS configuration.

## Breaking changes

### Coordinate the runtime upgrade

The runtime upgrade imports a new Ledger8Bridge host function. A validator still running an older node binary cannot instantiate the runtime and stops importing blocks when the upgrade is enacted.

Follow this order on each network:

1. Roll every validator onto Node 1.0.300.
2. Confirm that no validator is still running an older binary.
3. Enact the runtime with `set_code` only after all validators are upgraded.
4. Confirm that the runtime reports spec_version 1000300 and transactionVersion 3.

The runtime upgrade changes system_version from 1 to 3. See the [official release](https://github.com/midnightntwrk/midnight-node/releases/tag/node-1.0.300) for the runtime artifact hashes and governance proposal details.

### Reset devnet to the regenerated genesis

Devnet only: the genesis hash changes to `0xe50ea0ab2997fab2ea6fce3c198f4ff34e6c4f3e7747c133746053a0e82b60e5`. Wipe node state and reset the chain to the regenerated genesis before restarting. Update any indexer or downstream service that pins the old devnet genesis hash.

Preview, Preprod, and Mainnet do not require a state reset or re-sync.
