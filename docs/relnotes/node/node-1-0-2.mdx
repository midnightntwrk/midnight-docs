## High-level summary

Node v1.0.2 is a patch release on the [v1.0.0 GA line](/relnotes/node/node-1-0-0). It corrects how the node validates the first transaction of a block against the block timestamp, which had caused nodes to disagree on transaction validity and stalled Preview at block 128536. It also moves the ledger 8 dependency to the [ledger 8.1.2 security release](/relnotes/ledger/ledger-8-1-2) and clears security scanner findings in the toolkit image.

The runtime stays at 1.0.0, so no runtime upgrade is required. Operators update the node binary or image.

The changelog attached to the GitHub release is cumulative and repeats changes that already shipped in v1.0.0 and v1.0.1. The changes listed below are the delta from v1.0.1.

---

## Audience

This release note is relevant for users who:

- Run Midnight node infrastructure on any network. The block timestamp correction has a cutoff date after which nodes that have not synced past the affected historical blocks stop applying it, so update before then.
- Run the node toolkit image and have security scanning on their images.

DApp developers do not need to take any action for this release. The ledger 8.1.2 change tightens what the node accepts from the network; well-formed transactions are unaffected.

---

## What changed (Summary of updates)

The updates below describe the key changes introduced in this release.

- Fixed inconsistent transaction validation caused by a warm validation cache verifying transactions at a different block timestamp than the block they were included in.
- Limited the block timestamp correction to the first ledger transaction of a block and measured it from the parent block timestamp, which unblocked Preview at block 128537.
- Extended the cutoff after which the correction is disabled to 31 October 2026 (UTC), so networks can sync past the affected historical blocks.
- Added two node configuration values, `tblock_correction_offset` and `tblock_correction_disable_after`, with defaults that need no operator action.
- Moved the ledger 8 dependency from 8.1.1 to 8.1.2, a security release that hardens deserialization.
- Cleared critical and high findings in the toolkit image by bumping the bundled npm and applying npm audit fixes.

## Breaking changes

No breaking changes to the node interface. The runtime remains at 1.0.0.

Ledger 8.1.2 rejects non-canonical encodings and values that violate their type invariants, which 8.1.1 decoded. Transactions built with a supported SDK are unaffected. See the [ledger 8.1.2 release notes](/relnotes/ledger/ledger-8-1-2) for the details.

## Bug fixes and quality improvements

### Block timestamp correction for the first transaction of a block

A transaction validated from a warm strict cache on the producing node could be verified at a later timestamp than the block it landed in, so other nodes rejected the block. The node now accepts those historical transactions by applying a correction to the block timestamp used for validation. The correction applies only to the first ledger transaction of a block, is measured from the parent block timestamp, and is not applied on the mempool path. An earlier version of the correction was applied too broadly and stalled Preview at block 128536; this release imports that block.

Two configuration values control the behaviour and both have defaults:

```toml
# Must equal slot_duration_secs * (1 + MaxSkippedSlots): 6 * 2
tblock_correction_offset = 12
# Saturday, 31 October 2026 at 00:00:00 UTC
tblock_correction_disable_after = 1793404800
```

Sync nodes past the affected historical blocks before the cutoff; after it the correction is no longer applied. ([#1932](https://github.com/midnightntwrk/midnight-node/pull/1932), [#1964](https://github.com/midnightntwrk/midnight-node/pull/1964), [#1965](https://github.com/midnightntwrk/midnight-node/pull/1965), [#1995](https://github.com/midnightntwrk/midnight-node/pull/1995))

### Ledger 8.1.2

The ledger 8 pin moves from 8.1.1 to 8.1.2. The release hardens low-level deserialization across the ledger crates, guards `DustParameters::time_to_cap` against a zero decay rate, uses saturating arithmetic for DUST sequence and delta accumulation, and stops Zswap binding randomness extraction from panicking on a proof preimage without a witness. Crate versions: `midnight-ledger` and `midnight-zswap` 8.1.2, `midnight-onchain-runtime` 3.1.1, `midnight-storage` 2.0.3, `midnight-zkir` 2.1.1. ([#2145](https://github.com/midnightntwrk/midnight-node/pull/2145))

### Toolkit image security findings

The bundled npm in the toolkit image moves from 11.11.0 to 11.18.0, which clears a critical `tar` advisory and the other flagged packages vendored inside the npm CLI. npm audit fixes for `toml`, `nanoid`, `turbo` and `vitest` are backported to the release line. The toolkit version is unchanged. ([#1919](https://github.com/midnightntwrk/midnight-node/pull/1919), [#2145](https://github.com/midnightntwrk/midnight-node/pull/2145))
