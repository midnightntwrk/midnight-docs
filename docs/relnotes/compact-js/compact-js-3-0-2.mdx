## High-level summary

Compact.js 3.0.2 is the Compact.js release in the 1.1 patch to the ledger 9 networks. It builds the ledger 9 era against the final `@midnightntwrk/ledger-v9` 1.0.2 and `@midnightntwrk/onchain-runtime-v4` 4.0.2 packages from ledger 9.1.0.2, and its published packages declare those versions as the minimum. No Compact.js source file changed, and the ledger 8 era is unchanged.

Ledger 9.1.0.2 fixes contract calls that the networks rejected, so take Compact.js 3.0.2 through [Midnight.js 5.0.1](/relnotes/midnight-js/midnight-js-5-0-1).

Compact.js 3.0.1 was released the same day, built against release candidates of those packages. Skip it and use 3.0.2.

## Audience

This release is relevant for developers who:

- Move a DApp to Midnight.js 5.0.1
- Use `@midnight-ntwrk/compact-js`, `@midnight-ntwrk/compact-js-node`, or `@midnight-ntwrk/compact-js-command` directly

---

## Summary of updates

- Declares `@midnightntwrk/ledger-v9` `^1.0.2` and `@midnightntwrk/onchain-runtime-v4` `^4.0.2`, instead of the release candidate ranges in 3.0.1.
- Keeps `@midnight-ntwrk/compact-runtime` at exactly 0.21.0, so ledger 9 contracts still need Compact toolchain 0.36.
- Keeps the ledger 8 era on `@midnightntwrk/ledger-v8` 8.1.3 and Compact runtime 0.16.0.

If your project pins `@midnightntwrk/onchain-runtime-v4` to a release candidate, such as `4.0.2-rc.0`, through `overrides` or `resolutions`, remove that pin.

## Known issues

- `@midnight-ntwrk/compact-js` declares `^4.0.2` for `@midnightntwrk/onchain-runtime-v4`, while `@midnight-ntwrk/compact-runtime` 0.21.0 declares `^4.0.0-rc.3`. A fresh install resolves one copy. If your install resolves two copies, they reject each other's objects, so pin one version through `overrides` or `resolutions`. See [compact-js#42](https://github.com/midnightntwrk/compact-js/issues/42).
- When a process loads two identical copies of a compiled contract package, building a contract context fails with a `TypeError`. Deduplicate the contract package. See [compact-js#28](https://github.com/midnightntwrk/compact-js/issues/28).
- The CLI's `circuit` command rejects a valid null `--input-ps`, so it can't run a contract whose initial private state is `null`. See [compact-js#30](https://github.com/midnightntwrk/compact-js/issues/30).
