# Compatibility matrix

---

This compatibility matrix, also called the support matrix, lists the Midnight component versions tested against [Preview](#preview-support-matrix), [Preprod](#preprod-support-matrix), and [Mainnet](#mainnet-support-matrix). For releases that don't work with these versions, see [Known incompatible combinations](#known-incompatible-combinations).

Mainnet runs ledger 9 after the ledger 9 network upgrade. Preview and Preprod still run ledger 8, so their versions differ from Mainnet. For what changed and what to update, see [Ledger 9 upgrade](/relnotes/ledger-9).

:::note
This matrix only reflects the latest tested versions. Earlier versions may still work, but we do not guarantee compatibility or provide support for them.
:::

## Known incompatible combinations

Each network only accepts the versions for the ledger it runs. Preview and Preprod run ledger 8. Mainnet runs ledger 9.

### Preview and Preprod

Compact toolchains 0.34.0, 0.35.0, and 0.36.0 target ledger 9, and so do Compact runtimes 0.19.0, 0.20.0, and 0.21.0. They don't work with the versions in the Preview and Preprod matrices.

| Combination | Result |
|-------------|--------|
| Compact runtime 0.19.0, 0.20.0, or 0.21.0 with Midnight.js 4.1.1 | Midnight.js 4.1.1 pins `@midnight-ntwrk/compact-runtime` to 0.16.0 and `@midnight-ntwrk/onchain-runtime-v3` to 3.0.0. Compact runtime 0.19.0, 0.20.0, and 0.21.0 depend on `@midnightntwrk/onchain-runtime-v4` instead. Even when the toolchain matches the runtime, `deployContract` throws `Failed to configure constructor context with coin public key`. The coin public key isn't the cause: Midnight.js 4.1.1 doesn't support contracts compiled for ledger 9. |
| Compact toolchain 0.34.0, 0.35.0, or 0.36.0 with Compact runtime 0.16.0 | Importing the compiled contract throws `Version mismatch: compiled code expects 0.19.0, runtime is 0.16.0`. For toolchain 0.35.0, the expected version is 0.20.0. For toolchain 0.36.0, it's 0.21.0. |
| Compact toolchain 0.31.1 with Compact runtime 0.19.0, 0.20.0, or 0.21.0 | Importing the compiled contract throws `Version mismatch: compiled code expects 0.16.0, runtime is 0.20.0`. The message ends with the runtime version you installed, so for Compact runtime 0.21.0 it ends with `runtime is 0.21.0`. |
| Contracts compiled with Compact toolchain 0.34.0, 0.35.0, or 0.36.0, deployed to Preview or Preprod | These toolchains compile for ledger 9. Ledger 8 can't read the initial contract state of these contracts, so you can't deploy them to these networks. |

A bare `compact update` installs the newest toolchain and makes it the default. In a project that doesn't list the Compact runtime yet, `npm install @midnight-ntwrk/compact-runtime` without a version adds the newest runtime. To stay on the versions in this matrix, run `compact update <version>` and `npm install @midnight-ntwrk/compact-runtime@<version>`.

### Mainnet

After the ledger 9 network upgrade, most ledger 8 versions in the Preview and Preprod matrices don't work on Mainnet. The table and the paragraph after it list the cases. For the full list of changes, see [Ledger 9 upgrade](/relnotes/ledger-9).

| Combination | Result |
|-------------|--------|
| Transactions built for ledger 8, submitted to Mainnet | The ledger 8 transaction format doesn't decode on ledger 9, so Mainnet rejects these transactions. TBD-L9[exact error a ledger 8 transaction gets from a ledger 9 node] |
| Node 1.0.400 with Mainnet | A 1.0.400 node stops at the ledger 9 upgrade block. Upgrade directly to node 2.1.100. Node 2.1.0 release candidates aren't a supported upgrade step. The binary upgrade is one-way: once 2.1.100 opens a data directory, 1.0.400 can't start on it, so snapshot the data directory first. |
| Node 2.1.100 set to `storage_separation=unified` on an existing 1.0.400 data directory | The node stops importing blocks. The process keeps running with no crash and no peers, so liveness checks don't flag it. Keep the default `separate` storage layout for this upgrade. To move to `unified`, stop the node, delete the whole data directory (`chains/` and `ledger_storage/`), and resync. |
| Wallet SDK 1.x, including 1.2.0, with Mainnet | Wallets on Wallet SDK 1.x can't transact after the upgrade. Move to the wallet SDK version in the [Mainnet matrix](#mainnet-support-matrix). |
| Midnight.js 4.1.1 with Mainnet | Midnight.js 4.1.1 builds ledger 8 transactions, which Mainnet rejects. Move to Midnight.js 5. |
| Midnight.js 5 with a transaction built for ledger 8 | Midnight.js 5 throws `EraMismatchError` with the reason `ledger8-transaction-on-ledger9-network` and doesn't submit the transaction. |
| Wallet SDK 2 with a transaction built for the other ledger | Wallet SDK 2 refuses the transaction with `ProtocolVersionMismatchError`. |
| Indexer versions earlier than 4.4.100 with Mainnet | The 4.3 line doesn't index ledger 9, and versions earlier than 4.4.100 don't report DUST capacity correctly after the upgrade. Run the indexer version in the [Mainnet matrix](#mainnet-support-matrix), and re-index its database from genesis. |
| Contract action subscription without an offset, against indexer 4.4.100 | The subscription delivers only new actions. It no longer replays the contract's history. Pass an explicit offset, such as height `0`, to replay history. Midnight.js 5.0.0 does this. Midnight.js 4.x doesn't, so it receives no history. |
| Proof server 8.x with Mainnet | TBD-L9[whether proof server 8.1.3 can prove for ledger 9]. Use the proof server version in the [Mainnet matrix](#mainnet-support-matrix). |
| Contracts deployed before the upgrade, compiled with Compact toolchain 0.30.0 | These artifacts fail with `EraArtifactMismatchError`. Recompile the contract. TBD-L9[toolchain to recompile with] |
| New contracts compiled with Compact toolchain 0.31.1, deployed to Mainnet after the upgrade | Mainnet refuses the deployment. Compile new contracts with the toolchain in the [Mainnet matrix](#mainnet-support-matrix). TBD-L9[confirm after fork-survival test] |

Contracts deployed before the upgrade and compiled with Compact toolchain 0.31.1 keep working without a recompile. Configure the ZK config provider with `verify: 'warn'`, because toolchain 0.31.1 doesn't emit a `contract-manifest.json` file. Two limits apply: a call that spends a shielded coin the contract already holds fails, and contract maintenance after the upgrade needs a recompile. Calling a contract deployed before the upgrade, and deploying a contract compiled with Compact toolchain 0.36.0, are part of the tested upgrade rehearsal. TBD-L9[confirm after fork-survival test]
