## High-level summary

Ledger 9.1.0.0 is the first ledger 9 release. Mainnet moves to ledger 9 at the ledger 9 network upgrade on TBD-L9[fork date]. Preview and Preprod stay on ledger 8.1.3 until a later upgrade, which has no date yet.

Ledger 9 is a new ledger version, not a patch. After the upgrade, Mainnet rejects ledger 8 transactions, so DApps, wallets, indexers, and nodes that use Mainnet must move to the ledger 9 versions. Proof server 9.0.0 is the matching proof server. For what each role must do, and in what order, see the [ledger 9 upgrade page](/relnotes/ledger-9).

## Audience

This release note is most relevant for:

- Node operators and validators on Mainnet.
- DApp developers who deploy to or call smart contracts on Mainnet.
- Wallet developers and indexer operators who serve Mainnet.
- Developers who run the proof server against Mainnet.
- Developers who use the `ledger-v9` or `onchain-runtime-v4` npm packages directly, or the ledger Rust crates.

## Summary of updates

- Network: Mainnet runs ledger 9 after the ledger 9 network upgrade. Preview and Preprod run ledger 8.1.3 until a later upgrade.
- Compatibility: Mainnet rejects ledger 8 transactions after the upgrade. After the upgrade, wallet SDK 1.x can't sync on Mainnet, and Mainnet rejects transactions built with Midnight.js 4.x.
- Contracts: contract-to-contract calls and event emission, both in a first phase. TBD-L9[confirm feature list against final release notes]
- Cryptography: new primitives that circuits can use, including secp256k1, Keccak, and SHA-512. TBD-L9[confirm whether Ed25519 and P-256 ECDSA are in ledger 9 or ledger 10]
- Fees: a new minimum block price and a new cost model change the fee for the same transaction.
- DUST: DUST state resets at the upgrade, and cNIGHT-backed DUST generation is rebuilt automatically. TBD-L9[approved DUST wording: replace or confirm this paragraph]
- Proof server: proof server 9.0.0 is the proof server for ledger 9. Its default job capacity is now 10.
- Packages: `@midnightntwrk/ledger-v9` TBD-L9[ledger-v9 npm version, expected 1.0.0] and `@midnightntwrk/onchain-runtime-v4` TBD-L9[on-chain runtime version, expected 4.0.0] are on npm. ZKIR is TBD-L9[ZKIR version, expected 3.1.x].

## New features

### Contract-to-contract calls and events

A smart contract on ledger 9 can call another smart contract in the same transaction, and it can emit events. Both features are in a first phase. To use them, compile your smart contract with the Compact toolchain for ledger 9, TBD-L9[Compact toolchain 0.35.0 or 0.36.0], with language version TBD-L9[language_version]. TBD-L9[confirm feature list against final release notes]

### New cryptographic primitives

Ledger 9 adds secp256k1 and Keccak support, and SHA-512. TBD-L9[confirm feature list against final release notes] TBD-L9[confirm whether Ed25519 and P-256 ECDSA are in ledger 9 or ledger 10]

### Contract metadata limits

Ledger 9 stores the intermediate representation of each contract on chain, and it caps the size of the metadata for each entry point. A deployment whose metadata is over the cap fails. TBD-L9[confirm feature list against final release notes]

### Proof server 9.0.0

The proof server image for ledger 9 is `midnightntwrk/proof-server:9.0.0` TBD-L9[proof server tag]. The port stays 6300. The default job capacity changes from 0 (no limit) in proof server 8.1.3 to 10, so a busy proof server returns HTTP 429 when its job queue is full. To change the limit, set `--job-capacity` or the `MIDNIGHT_PROOF_SERVER_JOB_CAPACITY` environment variable.

On Mainnet, use proof server 9.0.0. On Preview and Preprod, keep using proof server 8.1.3. TBD-L9[can proof server 8.1.3 prove for ledger 9?]

## New features requiring configuration updates

None in this release.

## Deprecations

Ledger 8 is no longer accepted on Mainnet after the ledger 9 network upgrade. It stays in use on Preview and Preprod until their upgrade.

## Breaking changes or required actions

The ledger 9 network upgrade changes the ledger that Mainnet runs. Each role has its own steps, and the [ledger 9 upgrade page](/relnotes/ledger-9) lists them in order. In short:

- **Node operators and validators**: every Mainnet validator and RPC node must run node TBD-L9[node version, expected 2.1.100] before the governance upgrade. A node on the old version stops at the upgrade block.
- **DApp developers**: move to wallet SDK 2, Midnight.js 5, and an indexer on the ledger 9 line (4.4.x). Midnight.js 5 refuses to submit a ledger 8 transaction to a ledger 9 network with `EraMismatchError`, and wallet SDK 2 refuses a mismatched transaction with `ProtocolVersionMismatchError`. A transaction that is still pending at the upgrade ends in the `Orphaned` state.
- **Smart contract developers**: in a devnet test of the upgrade, smart contracts deployed before the upgrade and built with Compact toolchain 0.31.1 kept working without a recompile, when the ZK config provider uses `verify: 'warn'`. Artifacts built with toolchain 0.30.0 fail with `EraArtifactMismatchError`, so recompile those smart contracts. Contract maintenance after the upgrade also needs a recompile. TBD-L9[confirm after fork-survival test]
- **Indexer operators**: run an indexer on the ledger 9 line (4.4.x) and re-index from genesis before the upgrade. You can't upgrade an existing 4.3.x database in place.
- **Wallet developers**: wallets detect the upgrade when `protocolVersion` reaches 2000000 or higher. Drop any cached DUST tree indices at that point, because the indexer sends no dedicated reset event.
- **Proof server users**: on Mainnet, run proof server 9.0.0. TBD-L9[proof server tag]
- **Package users**: the ledger 9 npm packages are `@midnightntwrk/ledger-v9` and `@midnightntwrk/onchain-runtime-v4`. The npm version of `ledger-v9` doesn't match the ledger version: ledger 9.1.0.0 is `ledger-v9` TBD-L9[ledger-v9 npm version, expected 1.0.0]. Pin exact versions. Don't rely on the `latest` dist-tags of these packages, which have pointed to release candidates.

### DUST at the upgrade

TBD-L9[approved DUST wording: replace or confirm this paragraph]

DUST state resets at the ledger 9 network upgrade. On Mainnet, the network replays DUST generation backed by cNIGHT automatically, up to its full cap, so Mainnet holders don't need to register again. NIGHT bridged to Midnight after the upgrade needs a first-time registration. On Preview and Preprod, wallets will register again when those networks upgrade later. For about 3 minutes after the upgrade, while DUST is rebuilt, the network accepts no user transactions. If your DApp submits a transaction in that window, show a message that the network is upgrading, and retry.

### Fees

Ledger 9 sets a minimum block price of 10 and uses a new cost model, so the fee for the same transaction changes. Wallets and DApps that estimate fees must use the ledger 9 packages.

### Ledger error changes

If you match on ledger error names, `GenerationInfoAlreadyPresent` is now `InitialNonceAlreadyPresent`, and `BackingNightNotFound` is removed. New errors include `ZeroValueUtxo`, `ContractMetadataTooLarge`, and `IrNotFound`. TBD-L9[confirm ledger error changes against final release]

## Known issues

- Wallets and DApps that haven't moved to wallet SDK 2 can't sync or submit transactions on Mainnet after the upgrade. Check with your wallet provider for a ledger 9 release.
- Bridging NIGHT between Cardano and Midnight isn't covered by this release note. TBD-L9[bridge enabled at fork?]
- Block production rewards aren't part of ledger 9.
