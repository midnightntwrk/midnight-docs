# Create your first Midnight contract

This quick start takes you from an empty contract file to a message stored on a Midnight network. You write a Compact contract, compile it, deploy it to a local network, call it from TypeScript, and read the message back from the public ledger. Then you run the same code against the Preprod test network. Everything runs from the [example-hello-world](https://github.com/midnightntwrk/example-hello-world) repository, so each command here is one you can run as written.

## Prerequisites

- The Compact toolchain, version 0.31.1. Follow [Install the toolchain](./installation), then confirm with `compact compile --version`. This version compiles language version 0.23, which the contract declares. The [support matrix](../relnotes/support-matrix) lists the versions that each network supports.
- [Node.js](https://nodejs.org/) version 22 or higher.
- Yarn. The repository pins Yarn 1.22.22 in its `packageManager` field; if Corepack is available (it ships with Node.js 22 and 24), run `corepack enable` once and Yarn switches to that version automatically inside the project.
- [Docker Desktop](https://www.docker.com/products/docker-desktop/), or another Docker engine with Compose v2, running.
- Git.

## Setting up the project

Clone the example repository and install its dependencies. The repository ships the TypeScript code, the local network definition, and the test suite; you write the contract yourself.

### Procedure

1. Clone the repository and move into it:

   ```bash
   git clone https://github.com/midnightntwrk/example-hello-world.git
   cd example-hello-world
   ```

2. Install the dependencies:

   ```bash
   yarn install
   ```

### Verification

`yarn install` ends with `Done in` and a time. Run every later command from the project root, `example-hello-world`.

{/* _mod-docs-content-type: PROCEDURE */}
## Writing the contract

The contract stores one public message on the ledger and exposes one circuit that replaces it.

### Procedure

- Create `contracts/hello-world.compact` with this content:

   ```compact title="contracts/hello-world.compact"
   pragma language_version 0.23;

   export ledger message: Opaque<"string">;

   export circuit storeMessage(newMessage: Opaque<"string">): [] {
     message = disclose(newMessage);
   }
   ```

Here is what each part does:

- `pragma language_version 0.23;` declares the Compact language version the contract is written for. The compiler rejects the file if this doesn't match the version it compiles.
- `export ledger message` declares public, on-chain state: a field named `message` that holds a string. Anyone can read ledger state.
- `export circuit storeMessage` declares a circuit, the Compact equivalent of a function that a transaction calls. `export` makes it callable from your DApp.
- `newMessage` is a circuit argument. Circuit arguments are private by default, so the compiler refuses to write one to the public ledger unless you wrap it in `disclose()`. `disclose()` is your explicit statement that you intend to reveal this value.

### Verification

The file compiles in the next section. If you drop the `disclose()` call, the compiler stops with `potential witness-value disclosure must be declared but is not`, which shows the privacy check at work.

{/* _mod-docs-content-type: PROCEDURE */}
## Compiling the contract

Compiling turns the contract into a zero-knowledge circuit, generates the proving and verifying keys for it, and produces the JavaScript implementation and TypeScript types that your DApp code imports.

### Procedure

- From the project root, run the compile script:

   ```bash
   yarn compile
   ```

   The script runs `compact compile contracts/hello-world.compact contracts/managed/hello-world`.

### Verification

The compiler reports one circuit and its size:

```text
Compiling 1 circuits:
  circuit "storeMessage" (k=6, rows=26)
Overall progress [====================] 1/1
```

The output lands in `contracts/managed/hello-world`:

```text
contracts/managed/hello-world/
├── compiler/   contract-info.json, a description of the contract for other tools
├── contract/   index.js and index.d.ts, the contract implementation your code imports
├── keys/       storeMessage.prover and storeMessage.verifier
└── zkir/       storeMessage.zkir and storeMessage.bzkir, the circuit as text and binary ZKIR
```

## Running a local network

The repository's `compose.yml` starts a complete single-node Midnight network in Docker, so you can deploy without test tokens or a public network.

### Procedure

- Start the network:

   ```bash
   yarn env:up
   ```

   The script runs `docker compose up -d --wait`, which returns once every service passes its health check.

### Verification

`docker compose ps --format "table {{.Service}}\t{{.Image}}\t{{.Status}}"` lists three healthy services:

```text
SERVICE        IMAGE                                    STATUS
indexer        midnightntwrk/indexer-standalone:4.3.3   Up 8 minutes (healthy)
node           midnightntwrk/midnight-node:1.0.0        Up 8 minutes (healthy)
proof-server   midnightntwrk/proof-server:8.1.0         Up 8 minutes (healthy)
```

| Service | Local address | Role |
|---|---|---|
| Node | `ws://127.0.0.1:9944` | Runs the chain and accepts transactions. Uses the `dev` preset, network ID `undeployed`. |
| Indexer | `http://127.0.0.1:8088/api/v4/graphql` | Serves chain and contract state to the wallet and your code. |
| Proof server | `http://127.0.0.1:6300` | Generates the zero-knowledge proofs for your transactions. |

## How the TypeScript code deploys and calls the contract

The repository's test suite, `src/test/hw.test.ts`, is the DApp code for this quick start. It builds a wallet, wires up the Midnight.js providers, deploys the contract, calls `storeMessage`, and reads the ledger back. A DApp that talks to a Midnight contract from TypeScript follows the same pattern.

**The compiled contract.** `contracts/index.ts` wraps the compiler output so the SDK can load it:

```typescript title="contracts/index.ts"
export const CompiledHelloWorldContract = CompiledContract.make(
  'HelloWorldContract',
  Contract,
).pipe(
  CompiledContract.withVacantWitnesses,
  CompiledContract.withCompiledFileAssets(zkConfigPath),
);
```

`withCompiledFileAssets` points at `contracts/managed/hello-world`, where the keys and circuits live. `withVacantWitnesses` says the contract declares no witnesses; see [Private state and witnesses](#private-state-and-witnesses).

**The providers.** `src/providers.ts` builds the set of providers that deploy and call functions use:

```typescript title="src/providers.ts"
return {
    privateStateProvider: levelPrivateStateProvider({
        privateStateStoreName: `hello-world-${Date.now()}`,
        privateStoragePasswordProvider: () => 'Hello-World-Test-Password',
        accountId: wallet.getCoinPublicKey(),
    }),
    publicDataProvider: indexerPublicDataProvider(
        config.indexer,
        config.indexerWS,
    ),
    zkConfigProvider,
    proofProvider: httpClientProofProvider(
        config.proofServer,
        zkConfigProvider,
    ),
    walletProvider: wallet,
    midnightProvider: wallet,
};
```

- `privateStateProvider` keeps the contract's private state on your machine, in an encrypted LevelDB store.
- `publicDataProvider` reads contract state and transaction results from the indexer.
- `zkConfigProvider` loads the proving keys and circuits from `contracts/managed/hello-world`.
- `proofProvider` sends each circuit call in the transaction to the proof server, which generates its proof.
- `walletProvider` and `midnightProvider` are the wallet from `src/wallet.ts`: it balances each transaction, paying the fee in DUST, and submits it to the node. On the local network the wallet uses a seed that the node's `dev` preset funds at genesis, so you don't need a faucet.

**Deploying.** `deployContract` creates the contract on-chain and returns its address:

```typescript title="src/test/hw.test.ts"
const deployed: DeployedContract<Contract> =
  await (deployContract<Contract>)(providers, {
    compiledContract: CompiledHelloWorldContract,
    privateStateId: PRIVATE_STATE_ID,
    initialPrivateState: {},
  });

// ...
contractAddress = deployed.deployTxData.public.contractAddress;
```

**Calling a circuit.** `submitCallTx` runs `storeMessage` locally with the argument, has the proof server prove it, lets the wallet balance and submit the transaction, and waits until the transaction is on-chain:

```typescript title="src/test/hw.test.ts"
await (submitCallTx<Contract, 'storeMessage'>)(providers, {
  compiledContract: CompiledHelloWorldContract,
  contractAddress,
  privateStateId: PRIVATE_STATE_ID,
  circuitId: 'storeMessage',
  args: [message],
});
```

Both functions throw if the transaction fails on-chain, so reaching the next line means it succeeded. If the transaction never reaches the chain, the call keeps waiting rather than throwing.

**Reading the ledger back.** The indexer returns the contract's raw state, and the generated `ledger()` function decodes it into typed fields:

```typescript title="src/test/hw.test.ts"
const state = await p.publicDataProvider.queryContractState(contractAddress);
// ...
return ledger(state!.data);
```

The test then checks that `message` is an empty string right after deployment and `Hello World!` after the call.

## Deploying and calling the contract locally

Run the test suite against the local network to deploy the contract, store `Hello World!`, and read it back.

### Prerequisites

- The compiled contract from [Compiling the contract](#compiling-the-contract).
- The local network from [Running a local network](#running-a-local-network).

### Procedure

1. Optional: to see the message the test reads back, open `src/test/hw.test.ts` and add a `console.log` line to the `Stores Hello World!` test, after the ledger query:

   ```typescript title="src/test/hw.test.ts"
   const state = await queryLedger(providers);
   console.log(`Message on the ledger: ${state.message}`);
   expect(state.message).toEqual(message);
   ```

2. Run the tests against the local network:

   ```bash
   yarn test:local
   ```

## Private state and witnesses

Hello World keeps everything public: the message you pass in ends up on the ledger. Most Midnight contracts also work with data that stays on your users' machines, and they get it through witnesses.

A witness is a function that a Compact contract declares, for example `witness localSecretKey(): Bytes<32>;`, and that your DApp implements in TypeScript. When a circuit calls it, the witness supplies a private value, typically from the contract's private state. The circuit uses that value in its logic, and the proof shows that the logic ran correctly. The value stays off-chain unless the contract reveals it, for example by writing it to the ledger, and the compiler requires `disclose()` wherever that happens.

The Hello World code already carries the parts a witness needs, just empty:

- `CompiledContract.withVacantWitnesses` in `contracts/index.ts` registers no witness implementations, because the contract declares none. A contract with witnesses supplies them here instead.
- `privateStateId` and `initialPrivateState: {}` in the deploy call name and initialize the private state that witnesses read. The `privateStateProvider` stores it locally.

To write and use a witness, work through the [bulletin board contract](../tutorials/bboard/smart-contract) tutorial, which uses a witness to prove who posted a message without revealing their secret key, then see [Implementing witnesses for a contract](../guides/compact-javascript-runtime#implementing-witnesses-for-a-contract).

## Deploying to Preprod

Preprod is a public test network. The same test suite runs there, but the wallet needs test tokens: tNIGHT from the faucet, registered to generate the DUST that pays transaction fees.

### Prerequisites

- The compiled contract from [Compiling the contract](#compiling-the-contract).
- A wallet seed or 24-word mnemonic that you use only for testing. Create a new Lace wallet for this, because its recovery phrase also controls any Cardano or other funds in that wallet, and use its first Midnight account, which is the one the test suite derives. [Funding a wallet](../guides/acquire-tokens) covers the Lace setup.

### Procedure

1. Stop the local network if it is running, then start only the proof server. Your machine still proves your transactions:

   ```bash
   yarn env:down
   yarn proof:up
   ```

2. Copy the example environment file:

   ```bash
   cp .env.preprod.example .env.preprod
   ```

3. Edit `.env.preprod` and keep exactly one of the two lines: `MIDNIGHT_PREPROD_MNEMONIC` with your 24 words, or `MIDNIGHT_PREPROD_SEED` with a 64-character hex seed without a `0x` prefix. The repository's `.gitignore` already excludes `.env.preprod`; never commit it.

4. Fund the wallet with tNIGHT from the [Preprod faucet](https://midnight-tmnight-preprod.nethermind.dev/). The faucet is a web page with a captcha, so the test suite can't request tokens for you. Paste the wallet's unshielded address, the one that starts with `mn_addr_preprod1`. If you use a hex seed and have no Lace view of the address, the test suite logs it as `Your wallet address is: mn_addr_preprod1...` once the wallet finishes syncing. For the full steps, see [Getting tNIGHT from the faucet](../guides/acquire-tokens#getting-tnight-from-the-faucet).

5. Register the tNIGHT for DUST generation. In Lace, select **Generate tDUST**, as described in [Registering NIGHT for DUST generation in Lace](../guides/acquire-tokens#registering-night-for-dust-generation-in-lace). If the wallet has no DUST and holds unregistered tNIGHT when the tests start, the test suite submits the registration itself, but it doesn't wait for DUST to accrue, so the first deploy can fail if you register only at run time.

6. Run the tests against Preprod:

   ```bash
   yarn test:preprod
   ```

   The test loads the secret from `.env.preprod` and uses the public Preprod indexer and node, with your local proof server.

### Verification

The run follows the local one: the wallet syncs, logs its tNIGHT balance, and both tests pass with the message read back from the Preprod ledger. The first sync of a new wallet on Preprod scans the whole chain and can take more than an hour. The test suite allows up to 90 minutes for setup, and each run syncs from the start again, so keep the machine awake and on a stable connection.

## Troubleshooting

Failures you can hit on this path, with the message you see and the fix.

| Symptom | Fix |
|---|---|
| `yarn compile` fails with `error opening source file: failed for contracts/hello-world.compact` | The contract file is missing or misnamed. Create `contracts/hello-world.compact` as shown in [Writing the contract](#writing-the-contract). |
| `language version 0.23.0 mismatch` | The pragma asks for a language version your compiler doesn't compile. Install toolchain 0.31.1 with `compact update 0.31.1`, or match the pragma to your compiler. |
| `potential witness-value disclosure must be declared but is not` | A private value, such as a circuit argument, reaches the ledger without `disclose()`. Wrap it: `message = disclose(newMessage);`. |
| `Cannot find module './managed/hello-world/contract/index.js'` | The contract isn't compiled. Run `yarn compile` before the tests. |
| `Wallet.InsufficientFunds` on the first local transaction, right after `yarn env:up` | The wallet synced before its DUST became spendable. Run `yarn wait:dust`, which waits until the local wallet holds a spendable DUST coin, then rerun the tests. |
| `yarn env:up` fails with `container ...-indexer-1 exited (1)` on the first start | The indexer started before the node produced its first block. Run `yarn env:up` again; the second start succeeds once the node is up. |
| `Cannot connect to the Docker daemon` | Docker isn't running. Start Docker Desktop, wait for the engine to come up, then rerun `yarn env:up`. |
| `RPC-CORE: subscribeRuntimeVersion(): RuntimeVersion:: disconnected ... 1000:: Normal Closure` on stderr | Not an error. A connection closes normally during wallet setup, and the run continues. |
| `Either MIDNIGHT_PREPROD_MNEMONIC or MIDNIGHT_PREPROD_SEED is required for network 'preprod'` | `.env.preprod` is missing or empty. Create it from `.env.preprod.example` and set one of the two values. |
| `Set only one of MIDNIGHT_PREPROD_MNEMONIC or MIDNIGHT_PREPROD_SEED (both are defined).` | Delete the line you don't use from `.env.preprod`. |
| Preprod run sits on `Wallet sync [...]` lines for a long time | A new wallet scans the full Preprod chain on first sync. Leave it running. The pairs in parentheses, such as `dust=false (347113/1552182)`, show progress toward the chain tip; the number in brackets only counts log lines. |
